# Как пользоваться репозиторием: первая неделя 1.1

Репозиторий хранит учебные тексты, упражнения, код и твои работы. Материалы можно читать прямо в GitHub; для сохранения решений и вычислений удобнее локальная папка в VS Code. Расчёты .ipynb выполняются в твоём Python, а разбор начинается, когда ты присылаешь попытку в чат.

## 1. Открыть материалы сейчас

[Маршрут первой недели](../weeks/week01/README.md) — главный вход. Затем [практика P](../weeks/week01/00_tools.md): сначала P1–P3, после них [A](../weeks/week01/01_existence.md) и A1–A6. Перед B вернись к P4–P6. Далее B → C → D. МО, английский и исследование имеют отдельные часы в маршруте. Контроль — после A–D, отложенные проверки — позже.

Python и Git не нужны, чтобы начать читать и решать на бумаге. Не нужно проходить старые W01–W09 параллельно первой неделе. Приложение U1–U4 назначено позднее.

## 2. Получить рабочую папку на Mac

Рекомендуемый вариант с обновлениями: в VS Code открой Terminal → New Terminal. Из папки, в которой хочешь хранить курс, выполни:

```bash
git clone https://github.com/artyom4iklol/masterprogramm.git
cd masterprogramm
git switch -c study/week01
```

Если репозиторий уже клонирован, второй раз его не клонируй: открой существующую папку. Если учебная ветка уже создана, используй `git switch study/week01`. Если Git недоступен, начни с Code → Download ZIP на странице GitHub; возможность работать по учебным текстам от этого не меняется.

В VS Code: File → Open Folder → папка masterprogramm, содержащая course.json. Если скачан ZIP, папка обычно называется masterprogramm-main. Для .md открой файл и нажми Cmd+Shift+V: текст и формулы показываются в режиме просмотра. Изменения вносить нужно в исходный текст; Cmd+S сохраняет файл.

ZIP не является Git-копией, поэтому команды commit/push/fetch в распакованном архиве не работают. При дальнейшем переходе на Git сохрани свои файлы work/first_week, клонируй репозиторий и перенеси их в рабочую копию.

## 4. Как проходить одну тему

1. Прочитай назначенный фрагмент источника и объяснение урока; зафиксируй определения и непонятные переходы.
2. Закрой разобранный пример и восстанови его на бумаге. Затем переходи к упражнениям.
3. Для каждой задачи запиши постановку, основания, вычисления, проверку и интерпретацию. Не заменяй доказательство ссылкой на ответ.
4. Сохрани первую попытку до ключей. Если застрял, пришли условие/ID, попытку и точный вопрос; попроси одну подсказку.
5. После разбора отдельно запиши причину ошибки и повтори шаг без открытого решения. Если понадобилось готовое решение, для проверки самостоятельности нужен новый вариант.

Записывай фактическое время в submission.md. Базовая неделя 36 часов; резерв до 4 часов допускается по правилам маршрута. Это оценка, а не требование любой ценой завершить каждую задачу за её указанное число минут.

## 5. Где хранить ответы

Заполняй `work/first_week/submission.md` или создавай рядом `P_attempt01.md`, `A_attempt01.md` и т. п. Ссылки на эти файлы добавляй в журнал. Можно решать от руки: сохраняй фото/сканы в той же папке, например `A1_attempt01.jpg`. Формулы в Markdown можно оформлять через `$...$` и `$$...$$`; если это отвлекает от решения, используй бумагу.

Исправления сохраняй отдельно — `A_attempt02.md` или отдельным коммитом с пояснением причины. Первую попытку сохраняй до правки, чтобы разбор опирался на настоящую историю работы.

## 6. Как прислать работу на разбор

Достаточно прикрепить файл/сканы в чат. Не жди конца недели: сдавай законченный блок, например P1–P3. Укажи версию 1.1, время, где использовал помощь и что вызывает сомнение.

Если работа в GitHub, сохрани изменения и отправь учебную ветку:

```bash
git add work/first_week
git commit -m "Week 1: P1-P3 first attempt"
git push -u origin study/week01
```

В следующий раз сообщение commit меняется на соответствующий блок; ветка остаётся той же. Вход GitHub для push выполняется обычным способом через VS Code; пароль или токен в учебные файлы не вписывается. После push пришли ссылку на файл в ветке study/week01 или на конкретный commit. Автоматического чтения твоих обновлений и оценивания нет: я проверяю их по твоему сообщению. Если работа ещё только локальная, прикрепи файл в чат — ссылки на файл твоего Mac не дают мне доступа к нему.

Текст запроса: «Первая неделя 1.1, блок P1–P3. Вот моя первая попытка. Потратил … минут, помощь …. Сначала укажи первый неверный шаг и причину, задай вопрос для исправления; полный ключ пока не раскрывай».

## 7. Когда понадобится Python

Перед лабораторной D5 выполни [настройку Mac](SETUP_MAC.md). Установи расширения Microsoft Python и Jupyter, создай окружение по инструкции. Проверь `notebooks/00_environment.ipynb` с ядром Masters2027: это техническая проверка, не диагностика знаний.

Затем скопируй `weeks/week01/lab.ipynb` в `work/first_week/lab.ipynb` (VS Code: Copy → Paste) и работай в своей копии. Выбери Masters2027, заполни функцию consumer после письменного вывода D5 и выполни Run All. Пока функция не заполнена, PENDING ожидаем: это ещё не успешный результат. CSV сохраняется в work/first_week/lab_results.csv. Пришли копию notebook, CSV и письменный вывод.

`python course.py submit` — необязательная упаковка work/notebooks/research для сдачи; поэтому копия лабораторной должна лежать в work. Встроенные status/selfcheck/record-review относятся к старому банку W01–W09 и пока не оценивают новую первую неделю. Её журнал — submission.md, оценивание — после разбора. Зелёный GitHub Actions подтверждает технические проверки проекта, а не освоение материала.

## 8. Как получать обновления материалов

В Git-копии сначала сохрани и закоммить свои изменения. Затем в study/week01:

```bash
git fetch origin
git merge origin/main
```

Новые уроки попадут в твою ветку вместе с сохранённой историей решений. Если появился конфликт, пришли сообщение и список конфликтующих файлов: не выбирай удаление собственных ответов вслепую. После успешного слияния `git push` обновит учебную ветку на GitHub.

Для ZIP скачай новую версию в отдельную папку и перенеси свои ответы из старой work/first_week. Не распаковывай новую версию поверх единственной копии заполненного submission.md.

## Первое конкретное действие

Открой 00_tools.md, пройди P1–P3, сохрани попытки и время в work/first_week, затем пришли этот блок в чат. После разбора переходи к A. Остальная настройка может выполняться до лабораторной, когда она действительно понадобится.
